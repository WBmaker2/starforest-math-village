# 1학기 확장 구현계획 (2022개정 · 아이스크림 교과서 기준)

작성일: 2026-10-24 / 확정 사항: 전 학년 한 번에 · 1학기 마을 별도 · 2학기와 동일 분량 · 아이스크림 순서 고정

## 1. 목표

- 1~6학년 1학기 35개 단원을 2학기와 같은 분량·같은 엔진으로 추가한다.
- 첫 화면(입구)은 6개 학년 그대로 두고, 학년마다 [1학기 마을 열기][2학기 마을 열기] 두 버튼을 둔다.
- 기존 2학기 기록은 그대로 두고, 2학기 단원명도 아이스크림 정식명으로 고친다.

- 3학년(6곳): 1. 덧셈과 뺄셈 / 2. 평면도형 / 3. 나눗셈 / 4. 곱셈 / 5. 길이와 시간 / 6. 분수와 소수

### 2학기 (재배열·개명, 순서 변경 없음 확인됨)

## 4. 설계 (1학기 마을 별도)

- 입구: `assets/js/grades.js` doorCard에 학기 버튼 2개. 카드는 6개 유지.
- 라우팅: `?grade=N&sem=1|2` (없으면 2). 예) `lower/index.html?grade=1&sem=1`, `grade3/?sem=1`. 기존 2학기 링크 하위호환.
- 데이터: `g3-s1-data.js / g4-s1-data.js / g5-s1-data.js / g6-s1-data.js`, `low-s1-data.js` 신설. 껍데기 HTML은 그대로 두고 data 파일만 교체 로드.
- 저장소: `g3-store.js` 키 분리 `starforest-gNs1/s2` 또는 `grades:{g3s1,g3s2…}` 12칸. 전역(아바타·별·씨앗·텃밭)은 공유, `done/wrong/quests/stars2/recent/adaptLevel/lowDone`은 학기별 분리. 기존 `starforest-g3`는 2학기로 간주해 마이그레이션.
- 엔진: `g3-dialog/map/tags/quests/report/sheet/understand/collect`는 data 교체만으로 동작. 추가 작업은 `G3_EXPLICIT` 1학기 태그, `BASE_QUESTS` 학기별 ID(`s1-` prefix) 분기.
- 분량: 고학년 6단원×3차시×4문항=72문항/학년, 저학년 고정 3문항/집 + `LOWGEN-S1` 무한생성. 총 고정 약 321문항.
- 지도: 1학기 마을 지도 5종(새싹 1·2 + 별숲 3·4 / 5 / 6 컨셉) 신규 생성 — `docs/FLOW_IMAGE_PLAN.md`에 프롬프트 추가, ego-lite 생성 후 크로마 분할. 오기 전까지는 2학기 지도 색보정본으로 임시 표시.
- 공통: TRIALS 1학기 문제, TOWNS/PLAYS 학기 표시, 학습지·랭킹·리포트·신문 학기 필터, PWA 캐시에 s1 data 추가.

## 5. 순서

1. 기반: sem 라우팅 + 저장소 분리 + 입구 버튼 2개 (빈 1학기 마을 열림 확인)
2. 3-1 파일럿 6단원 (구조 검증)
3. 4-1 6단원 (각도·막대 교구)
4. 5-1·6-1 각 6단원 (통분·비율·부피 교구)
5. 1-1·2-1 11곳 (큰버튼·읽어주기 그대로)
6. 2학기 재배열·개명 + 공통(인쇄·랭킹·리포트) 학기 필터
7. 검증: 12개 마을 입장→차시→채점→저장→이어하기 매트릭스 + 교실 태블릿 실측 + UPDATELOG 기록

## 6. 검증·리스크

- 검증: 학년×학기 12개 전체 입장·풀이·저장·이어하기, 기존 2학기 기록 유지 확인, 모바일 지도 겹침 회귀 확인.
- 리스크: 저장소 키 늘어나면 용량 증가 → 학기별 done만 분리하고 전역은 공유로 억제. 출판사별 순서 차이 → 아이스크림 고정, 토글은 후순위. 지도 미완성 시 임시지도 사용 명시.
